# SAM Level 1B — controlled model transfer

Level 1B takes the exact confirmed model represented by Level 1A and creates one immutable snapshot package in the configured Ansys System Architecture Modeler (SAM) project through PySAM SysML2.

## Safety model

Level 1B never writes during normal UI refresh or model editing. A SAM write can happen only after all of the following steps:

1. The user opens **SysML V2 → Level 1 · Model**.
2. The user clicks **Send Level 1 to SAM**.
3. The server builds a no-write transfer plan for the current model.
4. The UI shows the target project, package, and source counts.
5. The user explicitly confirms the transfer.
6. The server recalculates the snapshot SHA-256 fingerprint. If the model changed after the plan was shown, the transfer is rejected.
7. PySAM starts transactional mode, creates the snapshot, and commits only when `stop_transactional_mode()` is reached.

If an exception occurs while the transaction is being built, `stop_transactional_mode()` is not called, so the incomplete local transaction is not intentionally committed.

## Idempotence

The transfer package name includes the first eight characters of the complete model snapshot SHA-256 digest:

```text
MBSE_Level1_<model-name>_<digest8>
```

Before writing, Level 1B calls `project.find_elements_by_name(package_name)`. If the same snapshot package already exists, no second write transaction is started and the UI reports **Already in SAM**.

A changed model produces a different digest and therefore a new immutable snapshot package. Update-in-place synchronization is intentionally deferred until the create-only transfer has been validated against the real SAM project.

## Native mappings

The writer follows `sysml/ArcadiaOA.translation.json` and does not invent a semantic fallback.

| Source semantic | SAM / SysML v2 element |
| --- | --- |
| Operational Capability | `RequirementUsage` |
| Operational Entity | `PartUsage` |
| Operational Actor | `PartUsage` with actor semantics |
| Operational Activity | `ActionUsage` |
| CONTAINS / DECOMPOSES | native ownership / nesting |
| PERFORMS | `PerformActionUsage` |
| Operational Exchange | `FlowConnectionUsage` |
| Communication Mean | `ConnectionUsage` |
| Supports Capability | `AllocationUsage` |
| Located In | `ReferenceUsage` |
| Operational Scenario | `ActionUsage` with ordered scenario steps |
| Scenario sequence | `Succession` |
| Characteristics | `AttributeUsage` plus source-value documentation |

The reusable ArcadiaOA definitions are also created inside the snapshot package, including OperationalEntity, OperationalActor, OperationalActivity, OperationalInformation, OperationalExchange, CommunicationMean, OperationalScenario, and OperationalCapability.

## Exact Level 1A trace

In addition to the native model elements, each snapshot contains one `TextualRepresentation` whose body is the same SysML v2 text generated by Level 1A. This gives the transfer an auditable textual representation without replacing the native model elements.

Each transferred source element and relationship also receives documentation containing its original MBSE-App source data and identifier.

## Unsupported semantics

The dry-run plan blocks the transfer if it finds:

- a source node type not declared in the ArcadiaOA translation contract;
- a relationship type not declared in the contract;
- a relationship whose endpoint types violate the declared mapping;
- a relationship whose endpoint is missing;
- an empty model.

Level 1B does not silently convert unsupported semantics into generic dependencies.

## Local configuration

Level 1B reuses the Gate 0 `.env` configuration:

```text
SAM_SERVER_URL=...
SAM_ORGANIZATION_ID=...
SAM_PROJECT_ID=...
SAM_ACCESS_TOKEN=...
SAM_USE_SSL=true
```

The access token remains server-side and is never included in the transfer plan or browser response.

## First real validation

Use the disposable SAM project already validated in Gate 0. Start the app and open the existing model:

```powershell
git fetch
git checkout feature/sam-level1b-sync
git pull
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python web_app.py
```

Then:

1. Open `http://127.0.0.1:5000`.
2. Load the model that was reviewed in Level 1A.
3. Open **SysML V2**.
4. Review the Level 1 text.
5. Click **Send Level 1 to SAM**.
6. Review the target project and package in the confirmation message.
7. Confirm.
8. Open the configured SAM test project and inspect the new `MBSE_Level1_...` package.

Do not use a production/important SAM project for the first Level 1B validation.
