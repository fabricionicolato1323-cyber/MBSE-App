# Conversational LLM Surface

## Purpose

The local LLM is an optional presentation layer. It does not own model semantics.
The Knowledge Graph, deterministic flow, user decisions, and write barrier remain authoritative.

## Runtime behavior

### AI off

The application uses the existing deterministic/guided wording unchanged.
No conversational LLM call is made.

### AI active

The application first decides the required question normally. Only then is the already-decided question sent to the local LLM for concise natural-language rephrasing.

```text
Guided / KG-driven process
        |
        v
Authoritative question
        |
        +---- AI off ----> render original question
        |
        +---- AI on -----> constrained verbalizer
                              |
                              v
                         render rephrased question
```

The options, answer structures, graph mutation, validation, and question order are not generated by the LLM.

## Hard separation of responsibilities

### Knowledge Graph and deterministic application logic

- determine semantic boundary and ambiguity;
- distinguish role realization from participant type;
- protect the System-of-Interest boundary;
- determine what information is missing;
- select the next modeling action/question;
- validate graph consistency;
- preserve user confirmation as authoritative;
- write to NetworkX only through the existing write barrier.

### Local LLM

- rephrase an already-decided question in natural English;
- verbalize `/ask` evidence that has already been retrieved from the Knowledge Graph.

The LLM is not used to:

- classify a participant;
- decide whether something is the System of Interest;
- extract candidate participants from a goal;
- decompose or semantically interpret activities;
- select the next question;
- create or modify graph facts.

## Safety/fallback behavior

The original question is used automatically when:

- AI is disabled;
- the local model is unavailable;
- the LLM returns an empty or multiline response;
- a quoted model name is changed or removed;
- an explicit `yes/no` contract is removed;
- the returned question is excessively long.

Questions are cached during the session so repeated prompts do not repeatedly call the local model.

## Web activation

Web sessions continue to start with AI off. The existing AI control activates a selected local Ollama model. `self.llm` is set only while AI is active, so disabling AI immediately returns the application to the original deterministic wording.

## Architectural rule

> The application decides what must be asked. The LLM only helps decide how to say it.
